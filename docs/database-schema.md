# Database Schema (Cloud Firestore)

This document outlines the schema for the HyFePoul Firebase database.

## Collections

### 1. `users`
Stores user profile information and notification tokens.
*   `uid` (Document ID): Firebase Auth UID
*   `email`: String
*   `createdAt`: Timestamp
*   `role`: String (e.g., "owner")
*   `fcmTokens`: Array of Strings
*   `farmId`: String (For future extensibility)

### 2. `devices`
Stores hardware registration, status, and the current UI state.
*   `deviceId` (Document ID): Unique identifier for the ESP32.
*   `ownerId`: String (UID of the claiming user)
*   `name`: String (e.g., "Main Coop Feeder")
*   `esp32Status`: String (`"ONLINE"`, `"OFFLINE"`)
*   `lastHeartbeat`: Timestamp
*   `settings`: Map
    *   `feedSchedules`: Array
    *   `thresholds`: Map
*   `currentState`: Map (Populated by the latest `DATA` payload)
    *   `feedWeightGrams`: Number
    *   `targetFeedGrams`: Number
    *   `hopperLevelPercent`: Number
    *   `waterLow`: Boolean
    *   `waterHigh`: Boolean
    *   `pumpActive`: Boolean
    *   `feedingActive`: Boolean
    *   `emergencyStopActive`: Boolean
    *   `timestamp`: String (ISO 8601 UTC)

### 3. `devices/{deviceId}/systemData`
Stores periodic historical snapshots of the device state.
*   `docId` (Auto-generated)
*   *(Matches `currentState` fields)*

*Data Retention Note: Scheduled Cloud Functions will prune old systemData to prevent runaway storage costs.*

### 4. `devices/{deviceId}/alerts`
Stores actionable event tracking and notifications.
*   `docId` (Auto-generated)
*   `eventId`: String (Generated by Mega, e.g., "42-1045", used for deduplication)
*   `timestamp`: String (ISO 8601 UTC)
*   `name`: String (e.g., "LOW_FEED", "EMERGENCY_STOP")
*   `resolved`: Boolean

## Secret Management Note
ESP32 device secrets (e.g., `X-Device-Token`) used for API authentication must **not** be stored in standard Firestore documents accessible to the mobile app. They are securely managed via Firebase/Google Cloud Secret Manager.
